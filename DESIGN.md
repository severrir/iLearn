# Design System: iLearn

## Overview

**Creative North Star: "The Free Play Cabinet"**

Every part on this site is a piece of arcade hardware. The header is a lit marquee sign, the promise line is a plate struck into the moulded cabinet body, the six track buttons are injection-moulded plastic key caps that genuinely travel down 4px when pressed, numbers are segmented LED readouts behind glass, and the code editor is a monitor sitting inside a dark bezel. Nothing is "a card with an icon on it" — ask what part of a machine it is first, then build that part.

The density is generous, not dense: one idea per block, big friendly shapes, 8px spacing steps, and one authored motion moment per section. The world is loud in colour and quiet in behaviour — things react when touched (press, lift, glow) but nothing moves on its own except the FREE PLAY lamp pulse, the mascot's blink, and the attract screen typing itself.

Two themes ship, dark by default (`:root`) and light on `:root[data-theme='light']`. Both themes carry the same parts; only the ground and the ink change. One surface deliberately does not change: the monitor.

**Key Characteristics:**
- Arcade hardware parts, never generic web widgets.
- Pinned palette from the client brief; no new hues.
- Chunky rounded display type (Baloo 2) against strict tracked mono labels (JetBrains Mono).
- Every number is a lit readout, every label is silkscreened mono.
- Phone-first: the 8-step level row scales and never wraps, code scrolls sideways instead of wrapping.
- Dark-and-light, but the screen is always dark.

## Colors

The palette is pinned by the client brief and is **not open to drift**: ground, cards, purple, mint, yellow, wine red and text are fixed values in `src/styles/tokens.css`, with light-theme counterparts in the `:root[data-theme='light']` block. Do not add a hue. If you need another colour, you need another use of one of these six.

### Primary
- **Arcade Purple** (`--purple`): the brand accent. Borders, link underlines, the drifting background symbols, the active-nav underline, timeline dots, the default key cap.
- **Fill Purple** (`--purple-fill`): used instead of `--purple` for any **solid purple block carrying white text** — primary buttons, the selected language half. It exists because the pinned purple only reaches 4.35:1 against white, which fails AA body text; the brief's other purple clears it. In light theme both tokens are the same value.
- **Link Purple** (`--link`): inline links in prose and the numbered rule counters. Lighter than the accent in dark theme because `--purple` on `#0f1226` does not read as text; in light theme it falls back to the fill purple.

### Secondary
- **Free-Play Mint** (`--mint`): success, "free", completed state. Fills the done level caps, the XP bar's right end, the focus ring, the lamp bulb, the editor caret.
- **XP Yellow** (`--yellow`): progress, the current position, "look here". Fills the current level cap, the lit indicator under it, badge dots, the challenge box outline.

### Tertiary
- **Georgian Wine Red** (`--wine`): one job only — the ground and border of the live/urgent state (`.livebar` sits on `--wine-wash` inside a `--wine` border). It is the same value in both themes. Never used for ordinary emphasis.
- **Lit Live Red** (`--live`): the lamp-family red for anything actually on air — the `.led--wine` readout and the glowing `.livebar__dot`. It is deliberately **not** `--wine`, which is too dark to read as lit on a dark panel. Wine is the housing; `--live` is the bulb inside it.

### Neutral
- **Cabinet Ground** (`--bg`) and **Card Navy** (`--card`): the page behind everything, and the flat content surfaces.
- **Moulded Body** (`--panel`, `--panel-hi`, `--panel-lo`): the plastic of the cabinet. `--panel-hi` is the top bevel catching light, `--panel-lo` the bottom bevel in shadow. Always used as a gradient between them, never flat.
- **Edges** (`--border`, `--border-soft`): one-pixel part seams. `--border-soft` is for internal dividers between rows of the same list.
- **Ink ramp** (`--text`, `--text-dim`, `--text-faint`): headings and strong text, body prose, and mono labels/meta respectively.

### Named Rules

**The Two-Tier Ink Rule.** Mint and yellow each ship as a pair. `--mint` / `--yellow` are the pinned brief values and are for **fills, large LED numerals, icons, borders and glows** — anything judged at 3:1. `--mint-ink` / `--yellow-ink` are for **small text (13px labels, the schedule times, checklist ticks) and for solid buttons carrying white**. In dark theme the pair is identical; in light theme the ink versions darken (`#08704f`, `#845d00`) because `#0f9f72` and `#a67600` hold 3:1 on white but not 4.5:1. If you are typing label-sized text or a filled button, reach for the `-ink` token; if you are filling a shape or drawing a border, reach for the plain one.

**The Monitor Rule.** The screen tokens (`--screen`, `--screen-panel`, `--screen-text`, `--screen-dim`, `--screen-border`, `--screen-mint`, `--screen-yellow`, `--screen-gutter`, `--screen-well`) **never flip with the theme.** A monitor is a monitor; the code box, the sample block, the output pane, the attract screen and the LED readouts stay dark in light theme. `--screen-well` is the darkest member of the set — the recess behind a readout or a line-number gutter, one step below `--screen` itself. This also means code contrast is identical whichever theme the learner picked. Using `--text` or `--card` inside a screen puts dark text on a dark surface — a real bug, not a style preference.

**The Washes-Not-Tints Rule.** Translucent accent surfaces come from the existing wash/edge tokens (`--purple-wash` + `--purple-edge`, and the mint, yellow and wine equivalents). Never hand-write a new `rgba()` of a brand colour.

## Typography

**Display Font:** Baloo 2 (weights 500–800; falls back to Noto Serif Georgian, then `system-ui`)
**Body Font:** Nunito (400/600/700/800 + italic 400; falls back to Noto Sans Georgian)
**Label/Mono Font:** JetBrains Mono (400/500/700)

**Character:** Chunky rounded headlines over plain warm body text, with every machine label set in tracked monospace. The contrast between the friendly display face and the strict mono labelling is what makes the page read as hardware rather than as a poster.

### Hierarchy
- **Hero** (800, `--t-hero` = 32px phone → 56px desktop, line-height 1.08, letter-spacing −0.015em): the home headline only.
- **H1** (800, `--t-h1`, 1.08): page titles in `.phead`.
- **H2** (800, `--t-h2`, 1.08): section headings inside `.sechead`.
- **H3** (800, `--t-h3`, 1.08): card and panel titles, the lesson header title.
- **Body** (400, `--t-body` = 17px, 1.5): all prose. Wrapped at 68ch in `.prose`, 62ch in `.lede`, 60ch under a section head, 44ch for the hero sub.
- **Small** (`--t-small` = 15px): card blurbs, nav links, list rows, FAQ text.
- **Micro / Label** (700, `--t-micro` = 13px, letter-spacing 0.08em–0.17em): every mono label — `.silk` section labels, `.plate`, `.spec` strips, `.badge`, footer column heads.
- **Code** (`--t-code` = 15px, line-height 1.65, ligatures off, `tab-size: 4`): the editor, samples, output, LED readouts.

### Hardware Label Sizes

Below 15px the site leaves the prose ramp and enters a second, separate ladder: the silkscreen and readout sizes. Every step is JetBrains Mono at weight 700 with its own tracking, and every step is in systemic use — these are not one-off tweaks.

- **14px** (`0.875rem`, line-height ~1.6): code that is shown rather than typed — the attract screen's demo program and its printed output (`.attract__code`, `.attract__out`) and the error print (`.out__err`), set one step under the live editor.
- **12px** (`0.75rem`): numerals struck beside a row — the rule counters (`.rules li::before`) and the schedule times (`.schedule time`).
- **11px** (`0.6875rem`, tracked 0.06–0.13em): the busiest label size. The FREE PLAY lamp (`.lamp`), the screen status bar (`.screen__bar`), spec strips (`.spec`), the lesson header badge (`.lhead__badge`), timeline times, the score leaders (`.score__name`), the track-card progress label and the impact stat labels.
- **10px** (`0.625rem`, tracked 0.04–0.1em): captions under a part — the key cap's sub-label (`.key__sub`), the step number and its label (`.step__n`, `.levelrow__label`), the countdown unit labels, and the mascot swatch and pose captions on `/about`.
- **9px** (`0.5625rem`, tracked 0.09em): the smallest part in the world — the Discord role pill (`.chat__role`). Nothing smaller ships, and nothing essential is said at this size alone.

Four more sizes sit off both ramps on purpose, because they are a part's own stamped size rather than text: the key cap label (1rem display, 800), the key glyph (1.45rem mono) with its 1.05rem echo on the track-card cap (`.trackcard__cap`), the wordmark (1.3rem, dropping to 1.1rem at ≤680px) and the chat avatar initial (0.9rem). Two label sizes are fluid because the part they sit in scales: `clamp(0.7rem, 0.5rem + 0.9vw, 1rem)` on `.step__key` so eight caps can shrink without wrapping, and `clamp(1.4rem, 1rem + 1.8vw, 2.1rem)` on `.led--lg`.

### Named Rules

**The Two-Ramp Rule.** There are two type ramps and they do not mix. The **prose ramp** (hero → h1 → h2 → h3 → 18 → 17 → 15px, Baloo 2 and Nunito) carries everything a learner reads as language. The **hardware ramp** (14 → 12 → 11 → 10 → 9px, JetBrains Mono 700, tracked) carries only machine labels and readouts: silkscreen labels, spec strips, LED digits, step numbers, status bars, role pills. Prose never drops below 15px, and a hardware label is never set in a prose face or size. When adding small text, decide which ramp it belongs to first — that decision also hands you its font, weight and tracking.

**The Georgian Display Swap Rule.** Baloo 2 has **no Georgian coverage**. `:lang(ka)` on `h1`–`h3` swaps the display face to Noto Serif Georgian at weight 700, line-height 1.22, letter-spacing 0 — the tighter Latin metrics clip Georgian ascenders. Body text under `:lang(ka)` uses Noto Sans Georgian, and `:lang(ka) .btn` drops to 16px in Noto Sans Georgian so labels still fit the pill. Any new display-sized text needs the matching `:lang(ka)` rule.

**The Silkscreen Label Rule.** Machine labels are always JetBrains Mono, weight 700, 13px or smaller, letter-spaced 0.06em–0.17em, in `--text-faint` on panel. This is the world's silkscreen; it is how a section head, a spec strip, a channel name and a footer column head all announce themselves. Never set a label in the display face, and never letter-space the display face to fake one.

**The Tabular Numbers Rule.** Any number that can change or line up (`.led`, `.spec`, `.score`, the schedule times, the countdown) carries `.tnum` or `font-variant-numeric: tabular-nums` so digits do not jitter as they tick.

## Layout

Content sits in `.wrap`: full width, `max-width: 1100px` (`--maxw`), centred, with a 16px side gutter (`--gutter`). Vertical rhythm is the 8px scale — `--s1` 8, `--s2` 16, `--s3` 24, `--s4` 48, `--s5` 96 — and sections use `.section` (`padding-block: clamp(40px, 7vw, 96px)`). Stacking inside a block uses `.stack-1/2/3` rather than per-element margins.

Phone-first, one column by default; multi-column layouts collapse at their own natural width rather than at shared breakpoints: hero bezel at 900px, lesson two-column at 980px, community at 880px, code box split at 860px, three-up at 760px, `.twocol` at 800px. The track key row goes 6 → 3 columns at 860px → 2 at 440px. Track cards are `repeat(auto-fit, minmax(290px, 1fr))`.

The marquee is `position: sticky; top: 0` with a 64px content box; the lesson header sticks under it at `top: 65px` and the lesson sidebar at `top: 130px`. `html` carries `scroll-padding-top: 80px` so anchors clear the marquee. The marquee's own nav collapses into a burger menu at 960px; at 680px the Join button and the theme/sound toggles move inside the open menu, and at 430px the wordmark's text hides — the mascot, the FREE PLAY lamp and the language switch never drop.

### Named Rules

**The Clip-Not-Hidden Rule.** `body` uses `overflow-x: clip`, **never `overflow-x: hidden`**. `hidden` makes `body` a scroll container, which silently stops every `position: sticky` descendant from sticking — the marquee and the lesson header both die. `clip` contains overflow without creating a scroll container.

**The Never-Wraps Rule.** The 8-step level row is `grid-template-columns: repeat(8, 1fr)` at every width and scales down instead of wrapping; its caps use `aspect-ratio: 3 / 4` and clamped type. Below 620px the step labels hide, but the eight caps stay in one row. Do not add a wrap breakpoint.

## Elevation & Depth

Hybrid, and physically motivated. Flat content surfaces (`.card`, `.note`, `.rules li`) sit on a soft ambient shadow (`--sh-1`) and lift 6px on hover to `--sh-lift`, which adds a purple edge ring. Cabinet parts instead get **moulded depth**: a gradient between `--panel-hi` and `--panel-lo`, a one-pixel inner highlight, and a hard-edged bottom bevel that compresses when pressed. Recessed parts (the plate, the screen, the LED, the XP track) use inset shadows so they read as struck or sunk into the body rather than floating.

### Shadow Vocabulary
- **Ambient low** (`--sh-1`, `0 2px 6px rgba(4,6,18,.5)`): resting cards.
- **Ambient mid** (`--sh-2`): the marquee, panels.
- **Ambient high** (`--sh-3`): the bezel, the open mobile menu.
- **Lift** (`--sh-lift`, `0 10px 26px … , 0 0 0 1px var(--purple-edge)`): hover on any clickable card.
- **Key bevel** (`0 5px 0 var(--key-shade)` + `0 9px 16px rgba(4,6,18,.5)` + `inset 0 1px 0 rgba(255,255,255,.5)`): the side wall of a moulded cap. Hover grows it to 7px and lifts 2px; `:active` collapses it to 1px and pushes the cap `translateY(4px)`.
- **Button bevel** (`0 4px 0 color-mix(... 55%, #000)` + blurred ambient): the same part logic on pill buttons; `:active` drops to 1px.
- **Recess** (`inset 0 2px 5px` to `inset 0 3px 22px rgba(0,0,0,.85)`): plate, screen, editor, LED, XP track.
- **Lit glow** (`0 0 Npx <accent>` or `text-shadow: 0 0 9px currentColor`): only on things that are actually lit — the lamp bulb, a done/current level cap, the XP fill, the LED digits, the live dot (`--live`).

**Shadow alphas belong to this vocabulary, not to the palette.** The bare `rgba(0, 0, 0, …)` and `rgba(255, 255, 255, …)` values inside `box-shadow` and `inset` declarations across `cabinet.css`, `editor.css` and `pages.css` are the depth of a recess and the sheen on a bevel, and they are intentionally theme-independent: a hole is dark and a moulding edge catches white light whichever theme is on. The depths in use are 0.3 (a cap's own seat), 0.45–0.5 (a struck plate, the XP track), 0.75 (the editor recess), 0.85 (a screen recess) and 0.9 (the LED well), plus `rgba(255,255,255,0.05–0.5)` for the top-edge highlight on panels, bezels and caps. Reuse one of those depths; never add a new accent `rgba()` here, and never read these alphas as palette colours.

### Named Rules

**The Offset-Plus-Blur Rule.** Every ambient shadow token carries both an offset and a blur. A hard zero-blur shadow is allowed **only** as the side wall of a part that compresses — key caps, pill buttons, step caps — and it must be paired with a blurred ambient shadow in the same declaration. A flat offset shadow on a card, panel or plate is not in this world.

**The Lit-Means-On Rule.** A glow states that something is powered: free play, done, you-are-here, running. Never use a glow decoratively on a resting surface.

## Shapes

Corners run as a ladder, and a part's radius states how big it is and how deep it sits. Four rungs are tokens: pill (`--r-btn: 999px`) for buttons, lamps, badges, roles and the XP track; 20px (`--r-card`) for cards, panels, notes, the challenge box and FAQ rows; 14px (`--r-key`) for moulded key caps, the track-card cap and the screen-surfaced boxes (`.ed`, `.sample`, `.out`); 10px (`--r-sm`) for small controls, plates, callout rows and inline chips. The bezel is the one larger corner (26px) because it frames everything inside it, and the large screens (`.screen`, `.attract`) are 16px.

Under the tokens sits a hardware ladder for small struck parts, each used where a token radius would read as moulded rather than machined: 13px the Read/Try/Ask icon tile (`.step3__icon`), 12px the step hit-area and the mini-runner disclosure (`.step`, `.mini`), 9px the level-row cap (`.step__key`), 8px the LED well (`.led`), 6px inline code and plate internals (`.ic`), 4px the focus-ring corner, the role pill and the Impact track dots, and 2px the lit indicator bar under the current step. Round dots, bulbs and avatars are true circles (`border-radius: 50%`).

### Named Rules

**The Smaller-Part-Smaller-Corner Rule.** Radius follows the size of the part, not taste: 26px a frame, 20px a card, 14px a key or screen, 10px a control, 9px a cap, 8px a well, 6px an inlay, 4px a hairline detail, 2px a lit bar. When adding something, take the rung of the part it physically resembles instead of inventing a value between rungs.

Borders are a single pixel of `--border`, read as a seam between two parts; the challenge box is the one 2px border, in `--yellow-edge`, because it is a marked-out task. The leader line in the score table is a 2px dotted rule, and the empty-state box is a dashed yellow outline — both drawn, never typed as dot characters.

## Components

Class names below are the real ones; type these.

### Buttons — `.btn`
- **Shape:** full pill (`--r-btn`), 56px tall (`--btn-h`), 26px side padding, display face at 800 weight.
- **Primary** (`.btn--primary`): `--purple-fill` with white, on a 4px bevel.
- **Mint** (`.btn--mint`): `--mint-ink` with `--on-mint`, same bevel — used for the Discord/join action.
- **Ghost** (`.btn--ghost`): transparent with a `--border` outline; on hover it **fills with `--text` and flips the label to `--bg`**.
- **States:** hover scales 1.05 and deepens the ambient shadow to the accent edge colour; `:active` scales 0.98 and collapses the bevel to 1px; both at 0.15s (`--d-press`). `[disabled]` is 0.45 opacity with no transform and no shadow.
- **Small** (`.btn--sm`): 42px tall, 18px padding, 15px text. `.btn--block` goes full width.

### Key caps — `.key`, `.keyrow`
The six track buttons, and the signature part of the world. Each cap takes `--key-cap` (the track's colour from `src/data/tracks.js`) and `--key-ink`; the face is a three-stop gradient (88% white-mixed top → cap → 84% black-mixed bottom), the side wall is `--key-shade` (`color-mix(in srgb, var(--key-cap) 55%, #000)`). Minimum 112px tall, 14px radius, display label with a mono `.key__glyph` (1.45rem) and a tracked mono `.key__sub`. `.key--done` adds a lit white dot top-right. Hover lifts 2px and brightens 1.08; `:active` drives the cap down 4px.

### Controls — `.ctrl`, `.lang`
Icon-only square-ish controls (42px, 10px radius, `--card` ground, `--border` edge) for theme, sound and the burger. Hover tints to `--purple-wash` with a purple edge; `[aria-pressed='true']` goes mint (`--mint-ink` on `--mint-wash`). `.lang` is two welded halves in one 10px rounded shell; the active half fills `--purple-fill` with white.

### Cards and panels — `.card`, `.card--hover`, `.panel`, `.trackcard`
- **Corner:** 20px. **Padding:** 24px (`--s3`). **Border:** 1px `--border`.
- `.card` is flat `--card` with `--sh-1`; `.card--hover` and `.trackcard` lift 6px to `--sh-lift` with a purple edge over 0.2s (`--d-lift`).
- `.panel` is the cabinet body instead: a `--panel` → `--panel-lo` gradient with `--sh-2` and an inner top highlight. Use a panel when the block is machine housing (Discord panel, score board), a card when it is content.
- Every track and lesson card carries a `.spec` strip (track · level · XP · minutes) in tracked mono.

### Inputs — the editor (`.ed`) and plain fields
- `.ed` is a dark screen (`--screen`) with a `--screen-border` edge, 14px radius and a heavy inner shadow. `:focus-within` turns the border `--screen-mint` and adds a 3px `--mint-wash` ring.
- A transparent `textarea` (`.ed__ta`) sits over a highlighted `<pre>` (`.ed__pre`); the caret is `--screen-mint`, selection is 40% purple.
- `.ed__gutter` is a 38px struck gutter of line numbers in `--screen-gutter` on `#070a16`.
- **`white-space: pre` with horizontal scroll — the editor deliberately does not wrap.** Wrapping looked tidier but hid the learner's own code at phone width and made every gutter number wrong below the first wrapped line. One logical line is always one row.
- Output (`.out`) wraps (`pre-wrap`), caps at 360px and scrolls; errors (`.out__err`) print in `--c-err` over a faint red wash. `.mini` is the yellow-wash disclosure that says the C / C# runner is not a real compiler.

### Navigation — `.marquee`
Sticky lit sign: a `--panel-hi` → `--panel` gradient, a 1px bottom border, and a `::after` tube of purple-to-mint gradient under it. Links (`.marquee__link`) are 700-weight 15px in `--text-dim`, 10px radius; hover tints `--purple-wash`, and `[aria-current='page']` adds `inset 0 -2px 0 var(--purple)`. The FREE PLAY lamp (`.lamp`) is a mint-wash pill with a pulsing bulb. See Layout for what drops at which width.

### Signature parts
- **Plate** (`.plate`): the promise, struck into the body — `--panel-lo` → `--panel` gradient, inset shadow plus a 1px `--panel-hi` lip underneath, tracked mono, `.plate__sep` separators in `--link`, `.plate strong` in `--mint-ink`.
- **Bezel + screen** (`.bezel`, `.screen`, `.screen__bar`, `.screen__body`): a 26px moulded frame holding a 16px dark screen with a scanline `::after` (2.8% white, texture only) and a mono status bar with a lit `.screen__dot`.
- **LED readout** (`.led`, `.led--lg`, `.led--wine`, `.led--yellow`, `.led__unit`): every number on the site. A `--screen-well` recess with an 8px corner and an inset shadow, tabular mono, `text-shadow: 0 0 9px currentColor`. `.led--lg` is the fluid large size; `.led--wine` burns `--live`, not `--wine`.
- **Level row** (`.levelrow`, `.step`, `.step__key`, `.step__n`, `.levelrow__label`): eight caps; `.step--done` fills mint-ink, `.step--now` fills yellow-ink and adds a 3px lit indicator bar underneath that always says where you are. The cap gradient top uses `--cap-lift` (86% dark / 96% light) — the lift differs per theme because dark caps carry dark ink and want a strong highlight, while light caps carry white ink and lose contrast if the dome top goes too pale.
- **XP bar** (`.xp`, `.xp__fill`): a 12px recessed pill track; the purple→mint fill is **always 100% width and revealed with `clip-path`** (0.7s `--e-out`), never an animated `width` — the gradient stays true instead of squashing and nothing triggers layout. The lesson header progress bar (`.lhead__fill`) does the same at 0.12s linear.
- **Score table** (`.score`, `.score__row`, `.score__name`, `.score__empty`): four metrics as LED readouts with a drawn dotted leader running out to each; `.score__empty` is the dashed yellow NO SCORES YET state.
- **Challenge box** (`.challenge`): 2px `--yellow-edge` on `--yellow-wash`, 20px radius, 24px padding.
- **Mascot** (`.bit`, `src/components/Mascot.jsx`): Bit, drawn here. Its four colours are **hardcoded hex in the SVG, not tokens** (`#2EF2B0` shell, `#7C5CFF` chest and limbs, `#FFD84D` antenna, `#0F1226` eyes) because Bit publishes a named reference sheet of those swatches on `/about` and must match it pixel-for-pixel in both themes. Do not tokenize them. Poses: `.bit--wave`, `.bit--think`, `.bit--cheer`, `.bit--pop`; the eyes blink on a 4s loop and the antenna bulb breathes at 2.6s.
- **Confetti** (`src/lib/fx.js`): fires only on a passed challenge, for one second, in the six key-cap colours read straight from `TRACKS[].color` — recolouring or adding a track recolours the celebration, instead of leaving a second copy of the palette behind to drift.
- **Drift** (`.drift`): fixed full-screen layer of mono symbols in `--purple` at 0.07 opacity, floating up over 8–15s.

### Motion
Timings are tokens: `--d-press` 0.15s (presses, hovers, tints), `--d-lift` 0.2s (card lift, cap state change), `--d-reveal` 0.5s (section fade-up), `--d-type` 1.5s (typewriter and counters). Easings: `--e-out` `cubic-bezier(.16,1,.3,1)` for reveals and lifts, `--e-press` `cubic-bezier(.3,0,.2,1)` for presses.

**The One Moment Per Section Rule.** A section gets exactly one authored moment: `.reveal` fades it up 24px once, the first time it scrolls in. Everything else in that section is a response to touch. Confetti fires only on a passed challenge.

**The Reduced-Motion Rule.** Under `prefers-reduced-motion: reduce`, `base.css` flattens all animation and transition durations to 0.001ms, `.reveal` starts visible, `.drift` is `display: none`, the attract caret hides, the mascot animations are `none`, and `fx.js` returns early from `confetti()` and the pop. New motion must be reachable by one of those switches, and nothing may be the only way information is delivered.

## Do's and Don'ts

### Do:
- **Do** build new elements as cabinet parts: ask whether it is a lit sign, a moulded key, a struck plate, a recessed well or a screen, then reuse `.panel` / `.key` / `.plate` / `.screen` instead of inventing a container.
- **Do** use `--mint-ink` / `--yellow-ink` for label-sized text and for solid buttons carrying white, and plain `--mint` / `--yellow` for fills, large LED numerals, icons, borders and glows.
- **Do** keep every screen-like surface on the `--screen-*` tokens so it stays dark in light theme.
- **Do** set every machine label in JetBrains Mono, 700, ≤13px, letter-spaced — and add a `:lang(ka)` rule whenever you add display-sized type.
- **Do** decide which ramp new text belongs to before sizing it: prose (≥15px, Baloo 2 / Nunito) or hardware (14/12/11/10/9px mono), then take the exact step.
- **Do** take a radius off the ladder by what the part physically is — 26 frame, 20 card, 14 key/screen, 10 control, 9 cap, 8 well, 6 inlay, 4 hairline, 2 lit bar.
- **Do** use `--screen-well` for the recess behind a readout or gutter, and `--live` (not `--wine`) for anything that is actually on air.
- **Do** derive decorative colour sets from data that already exists (`TRACKS[].color`) rather than writing a second palette.
- **Do** space with `--s1`–`--s5` and the `.stack-*` helpers, and keep content inside `.wrap` (1100px, 16px gutter).
- **Do** reveal progress with `clip-path` on a full-width fill.
- **Do** keep every number tabular (`.tnum`) and every count honestly zero.
- **Do** draw new icons into `src/components/Icon.jsx` on its 24px grid at 1.75 stroke with round caps, filling only genuinely solid objects.
- **Do** test both themes and a keyboard pass: the focus ring is a 3px `--mint` outline at 3px offset, and it must stay visible on every new control.

### Don't:
- **Don't** introduce a colour that is not in `tokens.css`, or hand-write an `rgba()` of a brand colour instead of using a `-wash` / `-edge` token.
- **Don't** put `--purple` (`#7c5cff`) behind white text — use `--purple-fill` for solid fills.
- **Don't** use themed tokens (`--text`, `--card`, `--mint`) inside a screen, editor, LED or attract surface; that is how dark text lands on a dark monitor.
- **Don't** change `body` to `overflow-x: hidden`; it breaks every sticky element on the site.
- **Don't** make the editor wrap, or add a wrap breakpoint to the 8-step level row.
- **Don't** animate `width` on a progress fill.
- **Don't** turn Bit's four hardcoded swatches into tokens or theme them; the `/about` reference sheet names those exact hexes.
- **Don't** invent a radius between rungs of the ladder, put a flat zero-blur shadow on a non-compressing surface, or glow something that is not powered on.
- **Don't** set prose below 15px or a hardware label at a prose size, and don't let 9px or 10px text be the only place a piece of information appears.
- **Don't** add a new `rgba()` depth to a shadow, and don't read the existing shadow alphas as palette colours — reuse the recess and bevel depths already named.
- **Don't** add a second authored motion to a section, and don't ship motion that reduced-motion cannot switch off.
- **Don't** letter-space Baloo 2 to fake a mono label, and don't set a heading in Nunito.
